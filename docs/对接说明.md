本文件维护本插件与官方 DeepSeek Harness（dsh）之间的对接进度：每轮官方发版后重新盘点一次，
更新下面的四类差异表与验证边界。Command Code CLI 侧的对接见
[模型与上游同步](agent-reference/model-catalog.md)与 `dsh-commandcode-upstream` 技能。

## 二、四类差异对照

| 类别 | 内容 |
| --- | --- |
| 双方都有 | 消息与内容块、结构化错误、凭据解析、易变设置、图片卸载、严格远端编解码、五个客户端插槽、会话费用投影、逻辑历史读取与精确分支边界、`addition-only`（仅新增）工具声明、`imageRequestTarget`（图片请求目标，本轮新接） |
| 上游有、我方未接 | `systemPromptUpdate: 'in-history'`（历史内系统提示替换）、原生工具延迟激活语义、`prepareCall` 可选准备回调、`TypertRemoteInfo` 的 `input({strict:true})` 与 JSON Schema（结构化模式）投影、远端访问控制资源声明（本版仅 owner 主体，无需声明）、平台预置模块表新增的 `zod` 与 `@tanstack/react-virtual` |
| 我方有、上游没有专用契约 | Command Code 账号轮换与网关探测、三协议 wire 转换、网关能力快照与价格展示、历史模型成本分析与固定工作量试算、`x-command-code-version` 与零数据保留请求头、压缩摘要的成本对账口径（`summaryTokens`） |
| 双方都没有 | 配置与凭据的跨服务原子事务、对在途请求追溯改写配置 |

差异细节：

1. **消息、内容与错误**：`RequestMessage`、`GenerateOptions`、`ContentBlock` 结构与 `LlmError` 构造本次均未变，
   适配器不需要改动。`LlmAdapter`（模型适配器基类）新增 `imageRequestTarget(provider, model, image)`，
   基类自带默认实现（归一化原图），因此不覆盖也不会链接失败；本插件已覆盖，见第五章。
2. **服务契约**：Agent 事件、设置、附件、会话投影的公开源码本次未变（附件、超时、启动环境、会话投影
   四个包的 `src/` 与基线逐字节相同）。凭据侧 `CredentialRef`／`credentialRef` 签名零变化，但**解析层序反了**，
   见第 3 条。
3. **上游行为变更一：凭据解析层序反转**。`$DSH_HOME/.credentials.yaml`（托管存储）现在**优先于**继承的
   进程环境；alpha.2 相反。`describe()` 恒返回 `writable: true`，写入不再因同名环境变量遮蔽而被拒
   （`assertUnshadowed` 整段删除）。插件只调用 `credentials.resolve()`、不自己拼层，因此代码不受影响；
   但两份 README 与[账号与重试](agent-reference/accounts-and-retry.md)原来的「环境变量优先」描述已经失真，已改。
4. **上游行为变更二：headless 不再挂载凭据**。`credentials`／`authorization`／`deepseek-account` 三行在
   headless（无头）装配层被有意关闭，一次性任务只认启动环境与 `.env`。插件对 `ctx.get('credentials')`
   一直有 `undefined` 守卫，服务缺席时回落到启动环境快照（process → 项目 `.env` → `$DSH_HOME/.env`），
   因此是**语义变化而非崩溃**：只在页面上存过 key、从未导出环境变量的用户，其 headless 运行会报
   `MISSING_CREDENTIAL`。按维护者决定**不反转上游装配**，只改错误文案与文档指引。
5. **上游行为变更三：远端协议新增访问控制**。alpha.3 引入 `remoteAccess` 服务、`Principal`（主体）与
   资源声明，网关对**非 owner** 调用做方法级授权。本版 `PrincipalMap` 只有 `owner`，本机浏览器 Peer 的
   主体恒为 owner，判定被短路，因此插件不需要声明 `resources`；这是一套尚未启用的骨架，将来引入非 owner
   主体时需要重新评估。
6. **新增但向后兼容**：`InvocationDescriptor` 增加两个可选字段（`description`）；`TypertCodec` 泛型化但
   协变兼容，插件手写的 `makeStrictCodec` 仍然合法；`TypertRemoteService` 与 `TypertSchema` 未变；
   `@deepseek-ai/dsh-typert-protocol` 新增 27 个导出（`Principal`、`TypertResource*` 等）与 `./remote-info`
   子路径，均为纯新增。
7. **破坏性变化（仅测试夹具）**：`TypertGatewayService` 的 `static inject` 由 `['typert']` 变为
   `['typert', 'remoteAccess']`；`InvokeRemoteRequest.peer` 由可选变必需。两者都只影响
   `scripts/verify-engine-load.mjs` 自建的探针组合，已适配，见第五章第 3 条。
8. **刻意未宣告的能力**：`in-history` 系统提示替换与原生工具延迟激活。能力标记必须与实际 wire 行为一致：
   插件继续使用前导系统提示与完整的活跃工具列表，未实现对应语义前不宣告这些能力。
9. **上游行为变更四：账号 provider 的 `models` 不再可配置**。alpha.3 把 `models` 从账号条目的配置 schema
   里剥离（`const { models: _protocolCatalog, ...protocolFields } = deepSeekConfigFields`），模型目录改由
   账号的 `/models` 列表接口提供，单模型调整走 `modelOverrides.<model id>`；解析时对
   `Object.hasOwn(options, "models")` 直接抛错，**空数组同样触发**。失败属可选条目
   （`did not activate` 只警告、不改变启动策略），非账号的 `llm-deepseek` 仍要求并接受 `models`。
   旧值会因升级而变成硬错误：alpha.2 及更早的账号包直接复用 `@deepseek-ai/dsh-llm-deepseek` 的 `Config`，
   而那里 `models` 带默认值且是易变（volatile）字段，设置层写入或清空后即落盘成 `models: []`。
   插件不读该条目配置，运行时不感知；本机残留的处置见[《决策记录》第八章第 10 条](决策记录.md#八dsh-引擎兼容范围与验证边界)。

## 四、验证证据与边界

1. **真实引擎矩阵**：`npm run test:engine` 对每个已声明引擎各跑一遍 —— 发布入口加载、静态具名导入审计、
   客户端 `require()` 种子审计、易变设置契约、持久化图片卸载契约、账号开通观察流取消、三协议 22 个流
   终态场景、网关切换期间的请求快照隔离、真实历史服务读取关闭会话与分支、严格分析远端校验。
   当前两个引擎（`0.2.0-rc.2`、`0.2.1-alpha.3`）全部通过；脚本按兼容记录自动选择这两版。
2. **逐引擎隔离安装**：`npm run test:install` 为每个已声明版本各建一个全新的 pnpm 10.34.5 generation，
   安装时把该版本的必需 Harness peer 一起钉死，再断言锁文件解析出的 `@deepseek-ai/dsh-llm` 恰好是目标版本。
   当前两个版本全部通过。
3. **类型与测试**：在**升级后的 alpha.3 开发依赖**下运行 `npm run typecheck` 与全量 948 项测试，均通过；
   `npm run build` 产出两段构建。这一步是此前只能靠源码推导的「类型面兼容」的实测证据。
4. **静态具名导入**：以真实 alpha.3 引擎逐条核对 `lib/index.js` 的 22 个静态具名导入（跨 6 个包），
   全部存在 —— 具名导入缺失是 ESM（ECMAScript 模块）链接期致命错误，必须单独证明。
5. **未覆盖**：浏览器实际渲染、真实账号与付费请求、凭据持久化、跨平台运行、长期运行稳定性，以及
   headless 下「导出环境变量后能正常发请求」的端到端表现，都需要实际环境验收，不能由本地绿色检查推定。
   压缩摘要的成本口径同样只做了折叠层与渲染层的单元验证，未跑真实压缩会话的端到端金额。
6. **本地环境残留（非插件缺陷）**：本机 web profile（`~/.dsh/profiles/web/cordis.patch.yml`）里
   `llm-deepseek-account` 条目的 `models: []` 属第 9 条所述旧值残留，按维护者决定暂不清理，因此 alpha.3
   本地启动会持续打印一条「1 entry did not activate」警告。该条目是上游账号 provider，失败为可选条目失败，
   commandcode 路由与其它条目的激活不受影响；此项未纳入自动化验证，也不构成插件缺陷。

## 五、本轮改动

1. **引擎声明替换**：`@deepseek-ai/dsh-*` peer 析取、`dsh.compatibility.dsh`、`engines.dsh`、`devDependencies`、
   `package-lock.json` 与 `dsh.compatibility.dshReleases` 同批由 `0.2.1-alpha.2` 替换为 `0.2.1-alpha.3`；
   `@deepseek-ai/cordis` 与 `@deepseek-ai/schemastery` 的范围**不变** —— alpha.3 配对的正是
   `4.0.5-alpha.2` 与 `3.18.5-alpha.2`，两者与既有范围分支同 major.minor.patch，已被覆盖。
2. **锁文件重建**：npm 的增量解析会把 `dsh-agent` 升到 alpha.3 却留下 alpha.2 的 `dsh-llm`，触发 peer 冲突；
   改为清除旧解析后一次性重装，29 个 `@deepseek-ai/dsh*` 包全部落在 `0.2.1-alpha.3`。
3. **测试夹具引擎感知适配**（`scripts/verify-engine-load.mjs`）：新增 `engineOwnerPeer()` 与
   `pluginEngineRemoteAccess()` 两个探测式助手 —— alpha.3 的网关需要 `remoteAccess` 服务才激活，
   且远端调用必须自带一个存活的 Peer；alpha.2 没有 `dsh-api-remote-access` 包、`dsh-client-connection`
   也没有 `Peer`（只有 `OperatorPeer`），因此按引擎能力探测，两版共用同一套探针。这是**测试脚本**改动，
   与发布产物无关，也解释了为什么「运行时零改动」与「夹具必须改」并不矛盾。
4. **新特性一：图片请求目标上报**。适配器覆盖 `imageRequestTarget()`，返回路由实际使用的请求目标
   （长边 1568、编码后 1 MiB）。此前宿主走基类默认实现，拿到的是归一化原图（例如 Retina 截图的
   2880×1800 与原始字节数），与实际发送的重编码版本不一致；截图类调用方因此会高估。改动约 10 行。
5. **新特性二：压缩摘要计入成本**。`compaction/summary` 事件带 `provider`／`model`／`usage`，但压缩走的是
   压缩器自己的 `ctx.llm.stream()`，不产生 `request/header` 与 `assistant/*`，所以既有的会话费用投影与
   历史分析**系统性漏计**；alpha.3 把自动压缩放进极简模式默认组合后，漏计从偶发变成常态。改动：
   - `src/cost-projection.ts` 折叠该事件，并在 `SessionCostFacts` 上新增 `summaryTokens`，记录「已折进
     `groups` 但不属于宿主 `tokenUsage`」的那部分；旧状态（没有该键）在 `parseState` 中补零而不是被拒绝。
   - `src/client/session-cost.ts` 的对账等式改为 `groups 合计 − summaryTokens === tokenUsage`，
     **保持严格相等**：两侧仍必须描述同一个耐久切面，只是把压缩这一项合法差异换算了出去。
   - `src/analytics.ts` 的 `foldRequests` 为摘要单独登记一条请求事实，只认事件自带的
     `provider === 'commandcode'`，且不打断前后请求的 turn/step 折叠状态。
6. **文案与文档**：`MISSING_CREDENTIAL` 文案补上 headless 指引（凭据服务不挂载，请导出环境变量或写
   `.env`）；`resolveRef` 注释写明层序随引擎变化；两份 README、[账号与重试](agent-reference/accounts-and-retry.md)、
   [客户端与设置](agent-reference/client-and-settings.md)、[引擎兼容](agent-reference/engine-compatibility.md)、
   [仓库地图](agent-reference/repository-map.md)、[模型成本与性能分析](模型成本与性能分析.md)、
   `CHANGELOG.md`、[决策记录](决策记录.md)、[提交历史](提交历史.md) 与 `dsh-release-upgrade` 技能同步更新。
   决策依据见[《决策记录》第八章](决策记录.md#八dsh-引擎兼容范围与验证边界)。
